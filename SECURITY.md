# Security policy and threat model

This is an evaluated local-first reference implementation, **not a production-certified service**. Report security issues privately to the repository owner; do not attach originals, credentials, personal data or public exploit details to issues. No organization-specific contact is invented.

## Implemented controls and evidence

| Threat / reference | Control | Evidence |
|---|---|---|
| ASVS authentication/access control | Argon2 password hashes, expiring HS256 JWT (required claims), server-side user/role lookup, no default credentials, owner checks, reviewer/admin dependencies | security.py; test_api.py |
| ASVS session/data protection | Token held in browser memory, no cookie auth or browser persistent token store; auth expires after 30 minutes | frontend api tests; JWT tests |
| ASVS validation / file processing | Extension+magic signatures, generated storage keys, upload cap, PDF/page/image/row/cell/text limits, XLSX ZIP count/ratio/expanded limits, no formulas/external links executed | pipeline.py; corrupt/resource tests |
| ASVS safe errors | Request IDs and stable codes; no raw native exceptions/document text in API failures | request schema/error tests |
| ASVS business logic | Decimal calculations, unknown currency fails closed, no auto-delete duplicates, explicit reviewer approval, optimistic version check and immutable snapshots | pipeline/API/version tests |
| ASVS audit | DB append-only triggers for audit updates/deletes; version updates denied; corrections recorded with actor/reason/version | append-only API test |
| LLM01 prompt injection | Source/observation untrusted, no tools, strict schemas, original ID/region/group/quote/whole-number grounding; unsupported values nulled | observation.py replay/adversarial tests; no semantic-completeness proof |
| LLM01 irrelevant and hostile uploads | Relevance guardrail rejects non-financial files before any model call; instruction-like text is flagged and stays data | test_guardrails_segmentation.py; live checks of a novel PDF and a hidden-instruction invoice |
| LLM02 sensitive disclosure | OCR, embeddings and Ollama are local; the gateway receives recovered text, so the operator must trust that endpoint; Anthropic requires ALLOW_CLOUD_EXTRACTION=true; gateway credentials stay in a git-ignored file | source inspection and vector/API isolation tests |
| LLM05 improper output handling | React escaped rendering, no raw HTML insertion, strict parser/schema checks | frontend evidence rendering; LLM tests |
| LLM06 excessive agency | No agent tools, autonomous actions or LLM reconciliation decisions | architecture; deterministic reconciliation tests |
| LLM10 unbounded consumption | Upload/source/context bounds, bounded child/SDK timeout, zero AI client retries, no automatic ambiguous AI resubmission; eligible offline retries capped at 3 | worker/source/observation tests; no spend cap or production DoS certification |
| Search authorization | Vector owner filter AND authoritative SQL authorization on every returned ID; keyword owner checks | cross-user keyword and mocked malicious vector hit tests; real embedded vector check |
| Supply chain | Exact resolved Python snapshot + npm lock; locally executed pip-audit and npm audit; CI not supplied | actual reports in eval/reports |

## Deployment requirements and residual risks

- Bind local development to 127.0.0.1. Use TLS, trusted reverse proxy, request-body limits **before multipart parsing**, and centralized ingress login/upload/search throttling in production. In-process rate limiting is not a distributed abuse defense. Multipart files can be spooled before per-file streaming checks; ingress caps are mandatory for hostile traffic.
- JWT_SECRET must have >=32 unpredictable characters and stay outside Git. Revoke access by removing the user/change signing key. No refresh cookie, logout revocation registry, MFA, account lockout or CSRF cookie flow is implemented. No cookies means no cookie-based CSRF surface; bearer endpoints still need correct proxy/CORS policy. Frontend refresh requires login again.
- No public file URLs or unauthenticated original-download endpoint. Local filesystem permissions/encryption are OS responsibilities; Docker volumes are not automatically encrypted. Run containers non-root. Native parser subprocess is a timeout/crash boundary, NOT a hardened sandbox. Apply network egress restrictions and memory/CPU limits at deployment.
- OCR is English mobile-model inference with uncalibrated scores, not assurance that every value is accurate. Review is deliberately conservative. Baseline and LLM outputs need human verification before financial action. Model false positives and zero-width/Unicode normalization ambiguities remain possible.
- The default provider is an OpenAI-compatible gateway set in the git-ignored `backend/app/gateway_settings.py`, or by `GATEWAY_*` variables. Never commit that file. All seven formats send recovered text, cell values, formulas, sheet names and layout metadata to that endpoint. No original PDF or image file is sent, but extracted text may contain the whole sensitive document, so verify the destination, document rights and retention first. `--provider local` keeps everything on the machine. The Anthropic provider also requires `ALLOW_CLOUD_EXTRACTION=true`. There is no hidden heuristic fallback, and Azure was removed.
- Actual and requested models and sanitized usage are recorded. Expired or ambiguous AI work is not resubmitted automatically, but manual reprocessing can charge again; the content-hash cache reuses finished requests. Byte and time limits are not a spending cap. Extraction response caches contain document data, so keep them private.
- The relevance guardrail is rule-based, not a security boundary. It can reject an unusual financial file, or pass a non-invoice containing financial words. Instruction detection uses patterns and will miss rewording, so prompt-injection defense relies on no model tools, strict schemas, grounding and human review.
- MinerU runs locally from a separate environment. Local-only model configuration is checked, and remote VLM URLs (including loopback) are rejected. Parser Markdown is derived text, not verified pixels or geometry. Native dependencies still need a hardened deployment boundary.
- `run.py` stores a generated JWT signing secret in the git-ignored `var/.jwt_secret`, protected only by OS file permissions.
- Private artifact runs contain copied originals, raw parser outputs, source blocks, observation, candidate/grounded values and sanitized model metadata. Keep originals/artifacts off public web roots and Git; apply OS ACLs/encryption. API retrieval requires ownership/admin and an allowlisted JSON filename; arbitrary nested filesystem download is not exposed. Structural coverage gaps block completion, but model-declared grouping/ignored sources and equal-value citations are not independent semantic verification.
- Reprocessing repeats source reading, while the cache skips finished AI requests. OCR has a total pixel budget; a long scanned file can be partial or hit the job limit. Do not claim unlimited 1000-page OCR throughput.
- Deletion removes DB derived data, original and private artifact runs plus Qdrant points when the index is enabled/reachable; a Qdrant deletion outage fails closed with 503. Audit retains only redacted metadata by policy. Disabling an already-used vector index before deletion needs an operator cleanup/rebuild. Filesystem cleanup after DB commit is not transactional. No retention scheduler, backup restore drill, crypto-erasure or guaranteed physical wiping exists.
- Corrections preserve originals and versions but human corrected facts are not source-grounded OCR facts. Reconciliation may conservatively report insufficient evidence after a correction. Validation re-runs; duplicate/reconciliation/vector projections are not all automatically recomputed after corrections. Reindex explicitly when needed.
- SQL JSON snapshots hold decimal strings rather than numeric relational financial columns. Do not use casts/float conversion for downstream accounting. No schema migrations beyond initial creation, DB encryption or PostgreSQL-specific hardening verified here.
- Text exports are not implemented, so CSV formula-injection exports are not exposed. Any future CSV export must neutralize cells starting =,+,-,@. Uploaded formula cells are data only, never evaluated.
- No antivirus, remote document URL fetching, autonomous agents, cloud OCR fallback, or arbitrary plugin execution exists. Datasets generated locally contain fictional identities. Do not upload real private data to evaluation tooling without explicit rights/consent.

## Operational verification

Run `python -m pip_audit -r requirements.lock.txt --format json --output eval/reports/dependency-audit.json`, `npm --prefix frontend audit`, and all tests. Latest results are in [eval/reports/test-results.md](eval/reports/test-results.md). A scan is a time-bound advisory check, not a warranty. No CI workflow or executed Gitleaks/Trivy scan is delivered. Add filesystem secret scanning, container scanning and protected CI before production; Docker/container execution is unavailable on the verified host.
